# Native Shift host comparison v4

Two **standalone experimental apps**, not patched OpenIDEA: stock AppKit + WKWebView and a minimal Tauri 2.12.4 / runtime-wry 2.12.2 / Wry 0.57.0 / Tao 0.37.1 host. Both load the byte-identical shared HTML via `loadHTMLString:baseURL:nil`. No xterm, product logic, plugins, user project, or user logs are included. Different bundle identities and host defaults remain potential confounds; this is a host isolation experiment, not a claim of identical OpenIDEA configuration.

Collection is off at launch. The baseline uses an application-local NSEvent monitor for physical Shift (56/60), returning the original event unchanged. It covers flagsChanged, keyDown and keyUp only in the test window (or windowless modifier events while the test window is this application's key window). No global event monitor, accessibility permission, SIP changes, other-process injection, network, or system preference changes.

An **independent, default-unchecked** advanced option wraps the actual input context's `handleEventByInputMethod:completionHandler:` if the selector and its void/object/block ABI exist. It installs an own method slot on the concrete class before replacing it, never an inherited superclass slot. Other instances and non-Shift calls directly forward. Stop restores the prior IMP if the installed IMP is still ours. Only the actual call is observed: original receiver, selector, event, one original invocation, and one original callback invocation for every callback received, on the original callback thread. No callback is synthesized or deduplicated. Missing or late callbacks remain pending/unobserved. Off-main entries are forwarded without observation. The private API may be absent, unused, or change; exported availability and callback counts distinguish this from handled=false. Hook timing can perturb behavior: keep hook-off results.

Both apps share the same bridge and probe implementation, which is itself part of the experiment. The local monitor reports dispatch before the responder chain; it does not claim to be WKWebView's flagsChanged entry. The optional input-context hook is the separate processing observation. Native object association applies only within the process. DOM/native correlation is temporal inference across a WebKit IPC boundary and different clock origins; an event's trusted flag does not prove human input. Aggregate modifier flags cannot identify a release when both Shift keys are held.

Privacy: sanitize before buffering, allowlisted Shift DOM identifiers and 16/229 only; other key/code/which fields are discarded. Text/composition events retain lengths only. No NSEvent description or characters access (flagsChanged characters can throw), terminal text, clipboard, commands, paths, or arbitrary stack traces. Memory is capped at 6000 records and stops at the limit. Export stops collection, uses NSSavePanel, and writes only on explicit confirmation. No automatic file writing on normal launch; UI/JSON require an explicit input-method label, initially unselected. The public TIS API is mapped to the fixed categories builtin-chinese/sogou/abc/unknown at start and native Shift events. Arbitrary IDs, custom names, and internal Sogou Chinese/English mode are never exported or inferred. The safe OS version and WebKit framework bundle version are included, not treated as proof of Safari's version. The apps do not spoof Safari or OpenIDEA bundle IDs.

`ProbeTests.m` is a separate native harness for exact forwarding, synchronous/delayed/background/missing/repeated callbacks, inherited-method isolation, teardown, privacy and buffer bounds. `test-page.mjs` tests focus, opt-in, redaction and repeated-run flow in Chromium. Explicit `--diagnostic-self-test` runs packaged host smoke with synthetic native flagsChanged, synthetic DOM events, canceled export, and close cleanup. This CLI mode never runs on ordinary launch. None of these tests establishes native Sogou behavior.

Build on standard ARM macOS: `bash tools/native-input/build-macos.sh`. Both bundles are ad-hoc signed, verified, smoke-tested, packaged together in a DMG, mounted and verified again. No notarization or signing secrets. Follow `使用说明.txt` for the minimal two-run user comparison. Investigate the advanced probe only after preserving the public baseline.

V4 fixes cold-start readiness. Start first confirms DOM focus through evaluateJavaScript, then checks native inputContext without blocking (50ms timer, 3-second deadline). A nil result stays preparing, not permanently unavailable. The advanced ready state requires the actual context and validated method installation; no sleep interval is treated as success. Early events remain recorded with sampleEligible=false. No input-method processing function is called to create readiness. Reading inputContext can itself warm up native state, so preserve the unchecked baseline.

Context loss/replacement and focus loss end the ready interval and detach the hook. Replacement gets a new epoch and readiness deadline. Callbacks retain the originating call/epoch; stale prior-session callbacks forward normally without entering the new buffer. Generation checks cancel stopped/closed/replaced asynchronous focus requests and timers. A failed readiness attempt remains exportable and cannot silently become a valid advanced sample. JSON includes transitions, context-check count, first-ready/install times, state at stop, and each row's readiness/eligibility. Export names include host, manual label, actual outcome and a random session suffix.

The macOS 26 ARM CI smoke starts in a new process with advanced selected on its FIRST Start, without earlier typing, baseline, or export. It waits for actual ready state and asserts a real input-context call/completion from synthetic Shift. Native tests cover nil-to-available via timer, nil/focus timeout, cancellation, stale focus acknowledgements, context replacement, old-epoch/prior-run callbacks, original exceptions, mandatory labels, source-category redaction, and the existing forwarding/privacy checks. These are not Sogou reproduction tests.
